# Christube Architecture (Phase 2)

## Runtime
- Monolithic PHP route files (server-rendered) at repository root.
- Shared bootstrap + helpers in `config.php`.
- Shared UI helpers in `includes/layout.php`.
- Shared styles in `public/styles.css`.

## Auth/Session Flow
1. `register.php` validates user input and stores `password_hash`.
2. `login.php` verifies password via `password_verify` and sets session user.
3. `requireLogin()` guards protected pages.
4. `logout.php` clears session.

## User/Profile/Channel Boundaries
- **Private account state**: password hash, session, account status.
- **Public profile state**: username, display_name, bio, avatar/banner URLs, channel-like identity.
- **Channel route**: `channel.php` (compatibility alias to `profile.php`).

## Centralized Mutation Pipeline
Mutating endpoints use `handleMutation()` from `config.php`.

Pipeline stages:
1. Enforce POST method.
2. Rate-limit check hook.
3. CSRF token verification.
4. Optional auth requirement.
5. Execute endpoint handler closure.
6. Normalize failure flash + redirect.

## CSRF
- Session token generated by `csrfToken()`.
- Forms include hidden token via `csrfInput()`.
- Verification through `verifyCsrfToken()` in mutation pipeline.

## Data Domains
- Users + profile/channel metadata
- Videos + visibility
- Comments + reactions
- Follows
- XP events + ad campaigns
- XMR point requests

## Reusable Includes/Layout
- `includes/layout.php`
  - topbar renderer
  - flash renderer
  - promoted sidebar renderer
- `public/styles.css`
  - shared auth/page/button/panel styles

## Testing
- `tests/integration_flows.php` validates critical integration wiring:
  - mutation middleware usage
  - CSRF form token wiring
  - auth hashing/verification presence
  - channel compatibility route existence
